## 4. Pipeline Workflow

### Phase 1: Complete the Validated Batch (9 handouts)

**What:** Voice rewrite + correction integration for the 9 validated handouts that need it (all except ACE-I Angioedema Grade A and the two that had in-session corrections).

**Workflow per session:**
1. Upload: Runtime Script + Collab Profile + Article VI Builder Master Prompt v1.1 + handout HTML + validation report
2. Builder integrates corrections into the handout while maintaining/enhancing Article VI voice
3. Output: revised HTML
4. Then: separate Lane 2 re-validation session on revised HTML (lightweight — focused on correction accuracy, not full audit)

**Session math:** ~2 handouts per Builder session = ~5 Builder sessions + ~5 re-validation sessions = **~10 sessions**

**For Physical Urticarias + Dermatographic:** These had in-session corrections (lane separation broken). They need a re-validation-only pass to confirm corrections didn't introduce issues. **~1 session.**

### Phase 2: Validate Remaining GitHub Handouts (~15)

**What:** Lane 2 validation of the ~15 unvalidated handouts already on GitHub.

**Workflow per session:**
1. Upload: HCTV Protocol v2.1 + handout HTML (lean upload)
2. Full Lane 2 audit
3. Output: validation report with grade

**Session math:** 2 handouts per session = **~8 sessions**

### Phase 3: Builder Polish for Raw Laptop Drafts (~120-140 handouts)

**What:** Article VI Builder voice polish for raw drafts. This is the bulk of the work.

**Priority order within this phase:**
1. **Tier 1 — Core allergy/immunology** (~40 handouts): Asthma, food allergy, environmental allergy, immunodeficiency, venom, drug allergy fundamentals
2. **Tier 2 — Practice differentiators** (~30 handouts): Contact dermatitis deep-cuts, mast cell, eosinophilic diseases, testing/immunotherapy
3. **Tier 3 — Ancillary topics** (~25 handouts): ENT, headache, eye, dermatology
4. **Tier 4 — General medicine / niche** (~20 handouts): POTS, TMJ, sleep, CHF, etc.

**Workflow per session:**
1. Upload: Runtime Script + Collab Profile + Article VI Builder Master Prompt v1.1 + raw draft (.doc/.docx)
2. Builder rewrites in Article VI voice with full reference list
3. Output: polished HTML handout

**Session math:** 1-2 handouts per Builder session (raw drafts require more work than corrections). Conservatively 1.5 average = **~80-95 sessions**

### Phase 4: Validate Builder-Polished Handouts

**What:** Lane 2 validation of everything produced in Phase 3.

**Session math:** 2 per session = **~60-70 sessions**

### Phase 5: Write New Coverage Gap Handouts (~10-16)

**What:** Create handouts for the critical gaps identified in Section 3.

**Workflow:** Voice-first (Builder writes from scratch with Article VI voice → Lane 2 validates → corrections if needed).

**Session math:** ~1 per Builder session + validation = **~20-30 sessions**

### Phase 6: Corrections + Re-Validation (ongoing)

Any handout graded B or below gets corrections → re-validation. Based on current data (~80% grade B), expect ~60-70% of Phase 4 output to need a correction pass.

| Phase | Sessions | Description |
|-------|----------|-------------|
| 1 | ~10 | Voice rewrite validated batch |
| 1b | ~1 | Re-validate Phys/Derm in-session corrections |
| 2 | ~8 | Validate remaining GitHub handouts |

| 6 | ~40-50 | Corrections + re-validation |
| **Total** | **~220-265** | **Full pipeline completion** |

**At 1-2 sessions per day, this is roughly 4-6 months of dedicated work.**

### Efficiency Recommendations

1. **Batch by domain.** Process all asthma handouts together, then all food allergy, etc. The Builder develops domain-specific voice calibration within a batch — switching domains mid-batch wastes context.

2. **Lean validation uploads.** Validation sessions need ONLY HCTV Protocol v2.1 + handout. No Starter Script, no Collab Profile. This saves ~30% context per session and allows 2-3 handouts per session.

3. **Skip duplicates before Builder polish.** Many topics have 2-4 versions (e.g., "The Skinny on Food Sensitivities" has 4 dated versions). Pick the most recent, discard the rest. This could cut Phase 3 by 20-30%.

4. **Triage ancillary topics.** Handouts on CHF types, Trisomy 21, TMJ — these may not need Article VI polish if they're not core to your allergy practice identity. Consider keeping them as-is or deprioritizing indefinitely.

5. **Defer translations.** Spanish/Pashto/Khmer handouts are a separate pipeline. Complete the English Article VI standard first, then translate validated English versions. Translating pre-protocol drafts wastes effort.

6. **Consolidate overlapping handouts.** Several topics have both a plan/algorithm AND an educational handout (e.g., "Asthma Handout" + "Asthma Action Plan" + "Asthma Control Test"). Decide which are standalone handouts vs. clinic forms vs. actionable plans. Not everything needs Article VI voice — action plans should be clean and functional, not literary.

## 6. GitHub Repo Management Recommendations

### Immediate Actions
- **Do not deploy** any unvalidated handout to patients
- **Do not remove** anything from GitHub — staging is fine
- **Tag validated handouts** with validation date and grade (consider a `validated/` subfolder or a manifest file)

### Naming Convention
Adopt: `condition_name.html` (lowercase, underscores). Already in use on GitHub. Consistent.

### Version Tracking
Add a `MANIFEST.md` to the repo tracking:
- Filename
- Validation date
- Grade
- Voice rewrite date (if applicable)
- Status: `validated` | `corrections-pending` | `pre-protocol` | `deployed`

### Deployment Gate
No handout moves to patient-facing status without:
1. Article VI Builder voice polish (confirmed)
2. HCTV Lane 2 validation (Grade B+ or above)
3. All MODERATE findings resolved
4. Re-validation if corrections were applied
